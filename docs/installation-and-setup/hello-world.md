# Hello World: Creating Your First Business Central Extension

In this walkthrough, we'll create a simple AL extension for Microsoft Dynamics 365 Business Central. The extension will display a message when the Customer List page opens.

We'll use our locally installed Business Central 27.12 environment.

## 1. Create an AL Project

### Step 1: Create a project folder

1. Create a folder named `HelloWorldBC`.
2. Copy its absolute path, for example:

   ```text
   C:\BC-Development\HelloWorldBC
   ```

3. Open Visual Studio Code (VS Code).

### Step 2: Generate the project

1. Press `Ctrl + Shift + P` to open the Command Palette.
2. Type `AL: Go!` and select the command.
3. Follow the prompts to select the project folder and target platform.

**Server selection:** The prompt's position in the sequence may vary. When asked to select a server, choose **Your own server**, since we're targeting a local Business Central installation.

**Target platform:** Select the appropriate option for your installed Business Central version. In this example, we're using Business Central 27.12.

The command scaffolds the project, generating files such as:

- `app.json` — defines the extension's metadata, version, dependencies, and compatibility settings.
- `HelloWorld.al` — contains our AL source code.
- `.vscode/launch.json` — configures the connection used for publishing and debugging.

If `launch.json` isn't generated, try reloading VS Code using `Developer: Reload Window` from the Command Palette, then run `AL: Go!` again.

### Step 3: Configure the connection

Open `.vscode/launch.json`.

The generated configuration may contain example values. Update them to match your local Business Central installation.

For example, the relevant properties may look like this:

```json
{
    "name": "Your own server",
    "request": "launch",
    "type": "al",
    "environmentType": "OnPrem",
    "server": "http://localhost:8080/BC270",
    "serverInstance": "BC270",
    "authentication": "Windows",
    "startupObjectId": 22,
    "startupObjectType": "Page",
    "breakOnError": "All",
    "launchBrowser": true,
    "tenant": "default"
}
```

These are illustrative settings based on our local environment. Preserve the other properties generated by VS Code, and verify the server URL and instance against your actual configuration.

**Important:** The Development Service port and web client port serve different purposes. In our environment, the Development Service is accessible at `localhost:8080`. Don't substitute the web client's URL without verifying the configuration.

### Step 4: Identify the server instance

If you don't know your Business Central Server instance name, open PowerShell and run:

```powershell
Get-Service |
    Where-Object {
        $_.DisplayName -like "*Dynamics*" -or
        $_.Name -like "*BC*"
    } |
    Format-Table Name, DisplayName, Status
```

**What does this command do?**

- `Get-Service` retrieves Windows services.
- `Where-Object` filters the results to services whose display names contain `Dynamics` or whose internal names contain `BC`.
- `Format-Table` displays the service name, display name, and current status in a table.

Example output:

```text
Name                             DisplayName                                             Status
----                             -----------                                             ------
BcastDVRUserService_16fd32       GameDVR and Broadcast User Service_16fd32              Stopped
MicrosoftDynamicsNavServer$BC270 Microsoft Dynamics 365 Business Central Server [BC270] Running
WebClient                        WebClient                                              Stopped
```

In this example, the Business Central Server instance name is `BC270`, as shown in square brackets in the display name.

Use your actual instance name in `launch.json`.

## 2. Download Symbols

### What are symbols?

Symbols are reference packages that describe objects exposed by Business Central and installed extensions.

For example, if your AL code references the standard `Customer` table or extends the `Customer List` page, the compiler needs information about those objects to validate your code.

Downloading symbols makes this reference information available to your development project.

### Download the symbols

1. Press `Ctrl + Shift + P`.
2. Type `AL: Download Symbols`.
3. Select the command and wait for it to finish.

If successful, the Output panel should display:

```text
All reference symbols have been downloaded.
```

The downloaded packages will normally be stored in the project's `.alpackages` folder.

If the download fails, verify that:
- Your server address and instance name are correct.
- The Development Service is enabled and accessible.
- Your `app.json` targets a compatible Business Central application version.
- Your authentication configuration matches the server.

## 3. Configure `app.json`

Before building the extension, confirm that your project targets the correct Business Central version.

Our environment is **Business Central 27.12**, with platform version `27.0.55363.0` and application version `27.12.55425.0`.

The relevant properties in `app.json` should be compatible with that environment. For example:

```json
"platform": "27.0.0.0",
"application": "27.12.0.0",
"runtime": "16.0"
```

These are version declarations, not the full installed build numbers. Keep the remaining generated metadata, including the extension ID and ID range.

For details, see Microsoft's [Choosing the AL runtime version](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/developer/devenv-choosing-runtime) documentation.

## 4. Customize `HelloWorld.al`

Open `HelloWorld.al` and replace its contents with the following code:

```al
namespace DefaultPublisher.HelloWorldBC;

using Microsoft.Sales.Customer;

pageextension 50100 CustomerListExt extends "Customer List"
{
    trigger OnOpenPage()
    begin
        Message('Hello World! This is my first published app.');
    end;
}
```

### Understanding the code

| Code | Explanation |
|---|---|
| `namespace DefaultPublisher.HelloWorldBC;` | Groups the object under a namespace to help organize and distinguish it from objects in other extensions. |
| `using Microsoft.Sales.Customer;` | Imports a namespace used to resolve relevant identifiers. |
| `pageextension 50100 CustomerListExt` | Declares a page extension with object ID `50100` and name `CustomerListExt`. |
| `extends "Customer List"` | Specifies the standard Business Central page that we're extending. |
| `trigger OnOpenPage()` | Defines code that executes when the page opens. |
| `Message(...)` | Displays a message to the user. |

**What's a page extension?**

Business Central provides standard pages, tables, and other application objects. A page extension lets us customize an existing page without modifying Microsoft's original object.

Here, we're extending the standard Customer List page and adding a message when it opens.

The object ID `50100` must fall within the ID range declared in `app.json` and must not conflict with another object in your extension.

## 5. Build and Run the Extension

1. Save your files.
2. In VS Code, select **Run → Run Without Debugging**.
3. The AL extension will compile your project and attempt to publish it to the configured Business Central environment.
4. If publishing succeeds, the web client should open.
5. Navigate to the Customer List page.

You should see:

```text
Hello World! This is my first published app.
```

If the build or publishing process fails, inspect the VS Code **Problems** panel and the **Output** panel for the AL extension's error details.

### What you've accomplished

You've created your first Business Central extension and experienced the essential AL development workflow:

1. Scaffold an AL project.
2. Configure the connection to Business Central.
3. Download symbols.
4. Write AL code.
5. Compile and publish the extension.
6. Test the extension in the Business Central web client.
